# Orkystra v0.1.0-rc.1 Release Notes

Date: 2026-07-02

Candidate tag target: `v0.1.0-rc.1`

## Summary

`v0.1.0-rc.1` is the first open-source release candidate for Orkystra as a self-hosted logistics control-tower platform. This candidate packages the product as an installable, documented evaluation stack rather than only an evolving development repository.

## Highlights

- Backend platform: .NET 9 API with protected operational endpoints, tenant-aware reads, audit scaffolding, health checks, bootstrap flow, persistence observability, MQTT event flow, and AI and optimization workflow orchestration.
- Operator frontend: Vue 3 control tower with API-backed overview, warehouse detail, transport sync and exception handling, AI recommendations, provider catalog editing, and operational trace visibility.
- Python services: FastAPI-based AI and route-optimization services with deterministic local fallback behavior when external runtime dependencies are unavailable.
- Deployment posture: local development, Docker Compose self-hosting, SQLite by default, and PostgreSQL support for multi-session self-hosted persistence.
- Open-source onboarding: root installation guide, contributor guide, release-candidate guide, smoke-test checklist, MIT license, changelog, and versioned release notes.

## Supported deployment posture

This release candidate is intended for:

- local single-tenant development with SQLite persistence
- self-hosted Docker Compose deployments
- self-hosted PostgreSQL-backed persistence for multi-session runs
- packaged or local Python AI and optimization services
- MQTT-backed event flow through the included broker

This release candidate is not yet intended for:

- managed SaaS multi-tenancy
- enterprise identity-provider integration
- centralized secret-manager integration
- zero-downtime upgrade automation
- HA or disaster-recovery topologies

## Key capabilities included

- Warehouse summary and detail projections with workbench-style operator cues
- Transport route detail, snapshot sync, longitudinal diffing, exception review, deferred follow-up, and handoff acknowledgement flows
- GPS telemetry publish and projection flow through MQTT
- Grounded AI recommendation workflow with swappable `http`, `local`, and `disabled` provider modes
- Bounded transport optimization workflow with explainable fallback output
- Provider catalog, runtime configuration editing, and local secret-entry support
- Operational persistence, audit visibility, and event-backbone observability endpoints

## Known limitations

- API-key authentication remains the current security baseline; external identity providers are not integrated.
- Several product slices still preserve deterministic fallback/demo behavior by design.
- AI grounding is based on request-time projections and deterministic heuristics, not live retrieval or long-term memory.
- Optimization is still scoped to a narrow route-sequencing workflow rather than fleet-wide planning.
- Secret storage is local-file or environment-variable based; there is no centralized secret manager or rotation workflow.
- The repository may contain additional in-progress changes outside the release-doc scope; cut the actual git tag only from an intentionally reviewed clean tree.
