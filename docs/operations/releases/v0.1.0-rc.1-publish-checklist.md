# Orkystra v0.1.0-rc.1 Publish Checklist

Use this document as the final manual handoff for publishing `v0.1.0-rc.1`.

## Scope

This checklist exists to make the final publication step unambiguous after the repository has already passed the sprint-level implementation, documentation, and preflight stages.

## Required artifact set

The candidate publication must include at least:

- `README.md`
- `INSTALL.md`
- `CONTRIBUTING.md`
- `CHANGELOG.md`
- `LICENSE`
- `PROJECT_STATUS.md`
- `IMPLEMENTATION_ROADMAP.md`
- `prompts/AUTOPILOT.md`
- `prompts/PROJECT_PROMPT.md`
- `docs/operations/release-candidate.md`
- `docs/operations/smoke-test-checklist.md`
- `docs/operations/releases/v0.1.0-rc.1.md`
- `docs/operations/releases/v0.1.0-rc.1-manifest.json`

## Final publication sequence

1. Review the current worktree intentionally.
2. Close, commit, or explicitly defer unrelated in-flight local changes.
3. Run:

   ```powershell
   powershell -ExecutionPolicy Bypass -File infrastructure/scripts/release-preflight.ps1 -Version v0.1.0-rc.1
   ```

4. Run the full verification set:

   ```powershell
   dotnet test backend/Orkystra.slnx --configuration Release /p:UseSharedCompilation=false /nodeReuse:false
   ```

   ```powershell
   cd frontend/web
   npm run build
   ```

   ```powershell
   cd python-services
   python -m pytest
   python -m compileall .
   ```

5. Confirm that:
   - `CHANGELOG.md` still matches the candidate scope
   - `docs/operations/releases/v0.1.0-rc.1.md` still matches the actual shipped behavior
   - `docs/operations/releases/v0.1.0-rc.1-manifest.json` still matches the artifact set
6. Create the tag from the reviewed `main` branch:

   ```powershell
   git tag v0.1.0-rc.1
   ```

7. Push the branch and the tag:

   ```powershell
   git push origin main
   git push origin v0.1.0-rc.1
   ```

8. Publish the release using:
   - release title: `Orkystra v0.1.0-rc.1`
   - release notes source: `docs/operations/releases/v0.1.0-rc.1.md`
   - artifact manifest source: `docs/operations/releases/v0.1.0-rc.1-manifest.json`

## Stop conditions

Do not cut or push the tag if:

- the worktree is still dirty without explicit intention
- the preflight fails
- the verification commands fail
- the release notes and manifest no longer match the actual repository state
- last-minute fixes would materially change the candidate scope

If any of the above happens, fix the issue on `main`, rerun the preflight and verification commands, then only cut the tag again when the tree is intentionally clean.
